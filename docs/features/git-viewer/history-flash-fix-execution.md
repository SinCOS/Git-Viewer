# UL021 历史与 Diff 加载期间保留画面

## 修改

用户反馈切换 Git Log 分支时界面闪白。原先 selectHistoryRef 在读取开始前立即清空 GraphRows、HistoryPage、提交选择与详情，导致下一帧移除提交列表，直到 Git 请求完成才重新创建。

现在将请求范围作为 loadHistory 参数传入，读取期间保留当前 HistoryRef、分页、提交列表、图形、选择和详情。结果成功后在同一 UI 回调中更新范围及内容；失败或取消保留原画面和原分页，沿用状态栏显示错误。加载期间仍使用已有禁用/取消/generation 机制。

同时移除 loadDiff 在请求前对 Preview/CommitDetails/lines 的清空，选择另一个提交或文件时保留已有预览，准备好后整体替换。首次加载和切换仓库仍使用原有空态/重置逻辑；成功切换历史范围后清理旧范围的提交选择和详情。

## 分支树与详情/刷新按钮的后续修正

用户进一步指出左侧分支树和右上角详情/刷新区域仍会出现刷新感。继续检查发现，读取成功后会用零值替换 HistoryList，导致列宽、滚动锚点及选择状态丢失；详情开关则在直接挂载历史与 Split 挂载历史之间切换，改变原生列表的父层级。

修正如下：

- 保留 HistoryList 实例及用户列宽，刷新后按提交 OID 重新定位仍在结果中的选中提交，保留已读取详情。
- 同一范围刷新覆盖用户已加载的分页范围，避免刷新将多页历史截断为首屏。翻页仍使用固定 OID 游标。
- 切换分支和输入搜索只调整滚动目标与选择，不用零值重建列表；切换分支成功后从顶部展示新范围。
- 历史区使用固定的 Row/Column 层级，详情仅作为相邻面板展开，历史表格始终挂载在同一父节点。详情分隔线继续支持鼠标拖动和左右键调整。
- 左侧目录折叠只影响树，不发起 Git 历史读取；点击已选中且未过期的范围沿用已有早退逻辑。

新增 120 条提交的 fixture 回归测试：加载两页、滚动后选中提交、反复折叠目录和开关详情、刷新不丢失列宽/滚动/详情；新增提交后按 OID 重映射选择；拖动与键盘调整详情宽度。

完整 `make check` 通过，包含全量 race 与 Go/MyGo 静态检查。随后补齐多页刷新后，重跑全部 History/Branch/布局相关 race 测试、相关 Go vet 与原生构建通过；`git diff --check` 通过。未新增人工 GUI/真实物理输入验收，不将 headless 交互测试视为真机无闪烁证明。

本次新增详情布局实现位于 `internal/ui/local/history_workspace.go`。

## 验证

新增真实隔离仓库回归测试，UI Dispatch 队列控制结果应用时机：

- 分支读取未应用期间，原范围、分页、提交文字和详情持续显示，不进入 Loading history 空态。
- 取消及迟到回调不改变原画面；读取失败保留内容并显示 Stale；重试成功时范围与列表一起切换。
- 提交详情和 Diff 等待替换时不清空，失败后保留最后成功预览。
